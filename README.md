# دیجی‌کالا — بازارگاه آموزشی جنگو

پروژهٔ تمرینی «دیجی‌کالا»: بازارگاهی کوچک با فروشندگان، مشتریان، سبد خرید چندفروشگاهی و پرداخت آزمایشی از کیف پول.
رابط کاربری فارسی و راست‌به‌چپ است و همهٔ محاسبات مالی سمت سرور با `Decimal` انجام می‌شود.

## فناوری‌ها

- Python 3.12 یا جدیدتر (پروژه با Python 3.13 توسعه یافته است)
- Django 5.2 LTS
- PostgreSQL 17 (با Docker Compose) و درایور Psycopg 3
- Pillow برای اعتبارسنجی تصاویر و python-dotenv برای تنظیمات محیطی

## پیش‌نیازها

- Python 3.12 یا جدیدتر
- Docker و Docker Compose (یا PostgreSQL 17 نصب‌شده روی سیستم)
- Git

## راه‌اندازی محلی

۱. فایل تنظیمات محیطی را بسازید:

```bash
cp .env.example .env
```

مقادیر `.env` را در صورت نیاز تغییر دهید. برای ساخت کلید امنیتی تازه:

```bash
python -c "import secrets; print(secrets.token_urlsafe(64))"
```

۲. محیط مجازی بسازید و وابستگی‌ها را نصب کنید:

```bash
python3 -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt
```

۳. پایگاه دادهٔ محلی را بالا بیاورید:

```bash
docker compose up -d --wait
```

۴. جدول‌های پایگاه داده را بسازید:

```bash
python manage.py migrate
```

۵. (اختیاری) کاربر ادمین بسازید:

```bash
python manage.py createsuperuser
```

۶. (اختیاری) دادهٔ نمونه را اضافه کنید:

```bash
python manage.py seed_demo
```

۷. برنامه را اجرا کنید:

```bash
python manage.py runserver
```

آدرس <http://127.0.0.1:8000/> را باز کنید. پنل مدیریت: <http://127.0.0.1:8000/admin/>

موجودی‌ها، سفارش‌ها یا رمزهای تغییرداده‌شده را بازنویسی نمی‌کند.

## اجرای آزمون‌ها

```bash
python manage.py test
```

آزمون‌ها روی همان PostgreSQL اجرا می‌شوند و یک پایگاه دادهٔ آزمون (`test_dijikala`) می‌سازند؛ بنابراین
کاربر پایگاه داده باید مجوز ساخت پایگاه دادهٔ آزمون داشته باشد (کاربر پیش‌فرض Docker یک ابرکاربر است).
آزمون‌های هم‌زمانی خرید با تراکنش‌ها و اتصال‌های مستقل به PostgreSQL اجرا می‌شوند.

## استفاده از PostgreSQL نصب‌شدهٔ موجود

اگر PostgreSQL 17 از قبل روی سیستم نصب است، به‌جای اجرای Docker Compose فقط مقادیر `POSTGRES_*` را
در `.env` مطابق سرویس خودتان تنظیم کنید و سپس `python manage.py migrate` را اجرا کنید.
برای اجرای آزمون‌ها، کاربر باید اجازهٔ ساخت پایگاه دادهٔ آزمون داشته باشد:

```sql
ALTER USER dijikala CREATEDB;
```

## مسیرهای اصلی

| مسیر | توضیح |
| --- | --- |
| `/` | صفحهٔ اصلی؛ فهرست محصولات از جدید به قدیم با جست‌وجو و فیلتر دسته‌بندی |
| `/stores/` و `/stores/<id>/` | فهرست فروشگاه‌ها و صفحهٔ هر فروشگاه |
| `/seller/` | پنل فروشنده؛ ساخت و مدیریت فروشگاه و محصول |
| `/customer/` | پنل مشتری؛ نام، تلفن، شناسهٔ حساب و موجودی |
| `/cart/` | سبد خرید چندفروشگاهی و پرداخت آزمایشی |
| `/payment/` | شارژ آزمایشی کیف پول |
| `/orders/` و `/orders/<id>/` | تاریخچه و جزئیات سفارش‌های مشتری |
| `/accounts/signup/`، `/accounts/login/`، `/accounts/logout/` | ثبت‌نام با انتخاب نقش، ورود و خروج |
| `/admin/` | مدیریت کاربران، فروشگاه‌ها، محصولات و سفارش‌ها (فقط کارکنان) |

## پرداخت آزمایشی

- شارژ کیف پول و پرداخت، شبیه‌سازی‌شده‌اند و به درگاه بانکی متصل نیستند.
- هنگام پرداخت، قیمت و موجودی دوباره از پایگاه داده خوانده می‌شود و مبلغ ارسالی از مرورگر مبنای خرید نیست.
- همهٔ تغییرها (کسر از مشتری، واریز به فروشگاه‌ها، کاهش موجودی، ثبت سفارش و خالی‌کردن سبد) در یک تراکنش
  اتمیک انجام می‌شوند؛ هر خطا همهٔ تغییرها را برمی‌گرداند.
- برای جلوگیری از کسر دوباره در ارسال تکراری، هر سبد شناسهٔ پرداخت (`checkout_key`) دارد که با هر تغییر سبد
  عوض می‌شود و سفارش ثبت‌شده با همان شناسه بازگردانده می‌شود.
- قفل‌ها با `select_for_update` به ترتیب مشتری، محصول‌ها (بر اساس کلید اصلی) و فروشگاه‌ها گرفته می‌شوند.
